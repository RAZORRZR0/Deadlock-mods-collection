# Detailed Post Scoreboard Menu

## Scope and routing

- This lane owns pak11, a standalone post-game stats board on the stock post-game Scoreboard screen: exact stats per player, souls by source, final items, MVP/Key Player slips and the soul lead graph. It is for any player and ships no VData.
- It is a fork of Observer HUD's Night Shift board (`observer_hud/panorama/**/observer_hud/pg_*`, forked 2026-10-29 from commit 5b0c767). User decision 2026-10-29: take the board out as a separate mod. User decision 2026-11-13: the two boards are kept in sync both ways. Observer HUD keeps its own board in pak10; a change to shared board logic goes into both copies, and the later or better version wins.
- Removed from the fork: match cards (team names, logos, organiser), aliases, the hosted store page (`CitadelHTMLPanel`) and the `ClientUI_FireOutput` handoff listener, plus the `oh_state.js` dependency (`parseClock` is inlined). The header shows the stock team names, and each plate shows the Steam name.
- Intentional difference, user decision 2026-11-13: a credit + donate strip (`#NSCredit` in `pg_board.xml`, `.NSCredit*` in the css, `MOD_VERSION` / `CREDIT_TEXT` / `DONATE_URL` / `openDonate` / `creditSet` in `pg_board.js`; each marked STANDALONE ONLY): `DETAILED POSTGAME V<MOD_VERSION> BY HANTURAYA | DONATE` (Ko-fi, `ExternalBrowserGoToURL`) at the bottom centre, under the stock page-nav row. It stays out of Observer HUD, which has its own branding; do not sync it there. Bump `MOD_VERSION` for a release. Release texts: the mod descriptions are `promo/gamebanana.html` and `promo/discord.txt`; the version changelog goes to `docs/changelogs/<date>_detailed_postgame_v<N>_builds.txt` (Bulk Add) and `_discord.md` (`# [Update N](link)`), shaped exactly like the previous version's files there and the `gamebanana-mod-page-writing` skill. Only `#NSCreditDonate` is hittable.
- Engine evidence and the board's live history are in `observer_hud/ENGINE.md` (Post-game page) and `observer_hud/LIVE-VERIFIED.md`. They were measured on pak10, not on this pak.

## Source boundaries

- Edit `detailed_postgame/panorama/`, `detailed_postgame/scripts/validate-detailed-postgame.js` and `build_detailed_postgame.ps1`. Never edit `_detailed_postgame_build/`, `dist/detailed_postgame/`, VPKs or archives. Of `observer_hud/`, edit only the board's own `pg_*` files and its validator, to keep the two boards in sync.
- Every pak path is under `detailed_postgame/`, so pak10's files are never mixed in. The only stock override is `post_game/citadel_db_page_post_game_new.xml`: the pinned stock page plus the `pg_loader.vjs_c` include, minus the Play Again flame `src` (the loader sets it with `SetMovie`). The validator checks it against `observer_hud/stock-pin.json`. When that pin moves, port the stock change here by hand.
- Only one pak can own that page. With pak01 (DLF) or pak10 (Observer HUD) also installed, their board shows (the lower pak number wins); `-Install` warns when an installed lower pak ships the page. ShowRank's `citadel_db_post_game_scoreboard_new.xml` does not clash with it.
- A board fix made in either fork is copied to the other in the same change (by hand, no tool does it). Only the team identity code (match cards, logos, organiser, aliases, `oh_state.js`) differs on purpose. Both validators must pass after a sync.

## Commands

```powershell
node detailed_postgame/scripts/validate-detailed-postgame.js
powershell -ExecutionPolicy Bypass -File build_detailed_postgame.ps1            # dist\detailed_postgame + dist\Detailed_Post_Scoreboard_Menu_<yy.MM.dd>.7z
powershell -ExecutionPolicy Bypass -File build_detailed_postgame.ps1 -Install   # also installs pak11 on this PC
node detailed_postgame/scripts/verify-timeline-live.js <metadata.json> [console.log|-] [label]   # live stat timeline E2E
```

- The validator runs the board in the same synthetic dashboard VM as Observer HUD's (copied, not shared) and writes `.tmp/detailed-postgame-validate.json`. It proves no rendering or CSS behaviour. `DPS_CHECK=<text>` runs only matching checks.
- The scripts ship unminified (no Closure step), so the validator tests the exact shipped source.

## Runtime rules

- Never write the stock graph tooltip's inline opacity: it beats the stock `.TooltipContainer` / `.TooltipVisible` rules, and the inherited inline `opacity: 1` kept the tooltip drawn after the mouse left the graph (user report 2026-10-29). The scan drops `TooltipVisible` after each synthetic hover and closes the last one with the column's stock `onmouseout`; off the Graphs screen a leftover `TooltipVisible` is removed. Evidence: `.scratch/m1_research/notes.md` (client.dll 6821 static RE, cross-checked with GPT-6 Astra).
- The header `#NSMatch` copies the match id with the stock `CitadelPostGameCopyMatchID()` dispatched from itself (its page callback copies the page's id). If that throws, the laid-out `#NSCopyEntry` TextEntry is the fallback. Live 2026-10-29: the stock route copied `121685912`.
- Never reparent stock scoreboard row children (fatal live). Restyle them in place and create own panels inside the rows through `pg_column.xml`.
- The board wakes on `CitadelMatchDetailsUpdated` and `CitadelPostGameSelectScreenIndex`, plus one check a second that reads only `PageVisible` while hidden (the `board:` budgets).
- Stat timeline (user 2026-11-23): after the scan, `scanTimeline` reads every stock graph column (40, evenly spaced; no per-minute data exists) and hovering a strip over the lead graph shows the board at that column; leaving restores the final board. Souls, kills, deaths and healing come from the general graphs in player mode, whose tooltip rows name a player only by colour (`#ColorBar` inline background-color = the graph button's `#PlayerColor`; the row's hero image has no heroid, live 6864). Players sharing a colour are separated by `untwin` (running totals, Souls by Source growth). Damage Breakdown gives player and objective damage per pick, re-picked every column with a drift check. Assists have no graph: final and dimmed while hovering. Healing over time has no barrier, so its row is labelled HEALING (NO BARRIER) while hovering. Healing by Type is not the player's healing for every hero: do not use it. E2E: `[DPS] data timeline` lines against the deadlock-api metadata with `verify-timeline-live.js` (kills and deaths exact from `death_details`).
- On a hovered graph column the best-of-12 stars (`NSBest` + `NSBest_<key>`) move to that column's highest players; assists keep the final ones. No rule may colour every hovered value (`.NSAtTime .NSCellValue`): it painted over the stat colours of the stars (user 2026-11-23).
- The stock Create Build button (`#CopyBuildButton`, last child of the row's `.PlayerRow`; C++ builds a local unpublished build from the player's purchases on click) is moved to the front of its own parent, never reparented, and floats at the portrait's top right while the card is hovered; the commend button floats top left (user 2026-11-23). Stock shows commend only with `.CanCommendPlayers`, i.e. in a match the viewer played (log `commend: offered` / `not offered`); test it on one of your own matches.
- Final item slots and buy times (user 2026-11-23; `scanItemNames` / `checkFlex` / `paintSlots` / `wantBuys` / `applyBuys` in pg_board.js). In game first: the stock row always has 12 CitadelModIcon panels, empty slots included; an icon carries no item id or name (probe `live/20261123-item-icons-probe-6864.log`), an empty slot's icon has none of isWeapon/isArmor/isTech, and hovering an item icon fills the stock CitadelModDetailsTooltip with its name one frame later (the TooltipManager layer is held at opacity 0, then set back to "1", never null). 9 slots are open, one more per enemy Walker killed (`Citadel_FlexSlotUnlockedSlot02-04`), from the lead graph's lane objectives (tier2, by killer team); trusted only if nobody ends with more items than their team's slots, no Walker falls in the first minute, and it is not Street Brawl (every player on the same souls; its lane objectives read as Walkers at 0:01, live 136872372: 71 items, 25 empty slots, framed, no locks). The cells are the stock icons, moved within their own container (`placeIcons`; the stock order comes back on teardown): the items owned at that moment in the order they were bought (no time yet: stock order), then the blank cells, the locks on the last ones. Blank = the icon's `modIconContainer` at opacity 0 plus an empty-slot frame (`NSSlotCell`, first child of the icon, full size: a 0 px box with overflow noclip drew nothing), with the stock lock image (`NSSlotLock`, no box: user) when locked. Never add children to ItemsContainer: the game rebuilds its children and drops foreign ones (live 2026-11-23). Panels inside stock rows take no board CSS, style them inline. Purchase times are not in the client: the save page's op `it` fetches deadlock-api match metadata, asked only on the first hover of the lead graph or of a player's items, cached per match for the session, retried after a minute when it failed; `#NSBuyNote` under FINAL ITEMS says when the match is too new or deadlock-api was not reached. Item ids = MurmurHash2 (seed 0x31415926) of the class name; `scripts/gen-item-names.js` writes the class names into the page (run after a patch adds items). Live 137998268: 125 items + 19 empty read (= the metadata's kept items), extra slots 2/3, 125/125 items timed after the first hover, purchase order kept.
- Row stats (user 2026-11-23, a GameBanana request for Statlocker's Match Summary views): a click on a row name turns that row through the stats of its kind (`ROW_FAMILY` / `cycleRow` / `KEY_INFO` / `paintCells` in pg_board.js; right click: back), e.g. TOTAL SOULS -> SOULS / MIN, KILLS -> KDA, DEATHS -> DAMAGE TAKEN -> TAKEN / LIFE, ASSISTS -> KILL PARTICIPATION, PLAYER DAMAGE -> damage / min, / life, bullet, headshot, ability, melee, OBJECTIVE DAMAGE -> OBJ. DAMAGE / MIN, HEALING -> HEALING ONLY -> BARRIERS. No stat is in two kinds, so no two rows show the same stat. The MORE menu of presets (BASE STATS, EFFICIENCY, ...) was removed as confusing (user 2026-11-23); a save holding a preset layout falls back per row to the row's scoreboard stat. The rows are saved in the hpv2-store page `dps/v1` (`prefs*`). Per life divides by max(deaths, 1) like Statlocker. Damage taken comes from the Damage from Players graph and reads 10-28 % above deadlock-api's player_damage_taken. Heal prevented, accuracy, last hits and the like are not readable in the client (row-variable probe in `live/`).
- Row hint (user 2026-11-23): "CLICK A ROW NAME TO SWAP" (`#NSRowHint`, `rowHint` in pg_board.js) shows over the row names until the player clicks one. It stays hidden until the save page answers or gives up, so it never flashes for a player who knows. A save written after a click carries `clicked: true`; an older save counts as clicked when its rows are not the scoreboard's. No answer: the hint shows until a click.
- Row bars (user 2026-11-23): hovering a row name shows a bar per stat of its kind on the middle of its bottom border, the shown one lit (`rowPips`, `#NSRowPips`, one strip out of the row-name column's flow, its y set per row from the 38 px row height; a click updates it). Live (pak11, 2026-11-23): HEALING showed three bars, the first lit.
- HEALING is healing + barriers (`healingWithBarriers` in pg_board.js; `{i:player_healing_healing}` + `{i:player_healing_barriering}`), as Statlocker and deadlock-api count it (user 2026-11-23). The stock `{i:player_healing}` also takes off the player's self-damage (match 137998268 metadata: Shiv 4,544 - 1,833 = 2,711, Lady Geist 34,686 - 18,118 = 16,568), and the stock AwardHealing star follows that number, so the board works out its own heal star. Every other scoreboard number matched Statlocker for all 12 players of that match.
- Review fixes (2026-11-23): Street Brawl hides row 1 by slot (`NSSlot0`), whatever stat it shows; a stat the graphs never give reads "-" once no graph read is pending (`graphsPending`), "..." only while one is; the saved rows are read again on the next show or click until a read is answered, a row clicked before the answer keeps its change while the others take the saved stat, and nothing is written before a read was answered; closing the page mid-hover restores the final board, and closing it while the graphs are read drops the board so the next show reads them again; "HEALING (NO BARRIER)" only when the Healing graph was read (`S.timeline.healRead`).
- Console lines use `[DPS]`. The `[DPS] data` lines are the E2E artifact.
